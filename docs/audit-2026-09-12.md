## Reproduced defects and next checks

P1 means fix before using real data or enabling a shared cloud pilot. P2 means
fix before marking the relevant feature complete. P3 is documentation cleanup.

1. **A1 / P1 — Cloud consent is not enforced through the operation lifetime.**
   In `apps/extension/entrypoints/sidepanel/SpeechAssist.tsx:489`, `fetchHelp`
   does not check consent; its button only sets `aria-disabled`. With a stored
   fictional credential and consent OFF, pressing Enter issued
   `POST /v1/speech/help`. Separately, start a fake recording, switch cloud OFF,
   and wait: `POST /v1/speech/transcribe` was still issued about 15 seconds later.
   The recording callbacks at lines 195–239 retain the earlier session, and
   revocation does not stop/discard them. Enforce consent at request time, abort
   pending work and stop/discard recordings on revocation. Add regression checks
   for off-state keyboard activation, mid-recording revocation and credentials
   removed while an operation is pending.

2. **A2 / P1 — Late scan replies can restore an obsolete document.**
   `apps/extension/entrypoints/sidepanel/useFormReader.ts:55` accepts direct scan
   replies after checking only the tab ID. Hold an already captured NSP reply,
   navigate that tab to ECI, wait for the stale state, then release the reply:
   the panel displays the old NSP OTR field beside the ECI page. `decideInbox`
   protects pushed messages, but not this path. Bind each request to a lifecycle
   generation and reject replies after navigation, close, unmount or a newer
   request. Exercise delayed direct replies, not only the pure inbox function.

3. **A3 / P1 — Common secret-field names bypass exclusion.**
   `apps/extension/entrypoints/reader.ts:24` uses ASCII word boundaries that do
   not split underscores. Synthetic controls named `otp_code` and `card_number`
   were returned with their values, while a control with `autocomplete="cc-number"`
   was correctly excluded. Normalize name/ID tokens and check standard secret
   metadata before reading any value or option. Add snake_case/camelCase,
   translated-label and group-member cases. Do not fix this by labelling every
   numeric value or postal PIN as a secret.

4. **A4 / P1 — The same credential can bypass its rate limit.**
   `apps/api/src/http.ts:82` keys limits by the raw Authorization header before
   authentication normalizes it. With a one-request limit, the same valid token
   returned statuses `200, 429, 200, 200` when sent with one, one, two and three
   spaces after `Bearer`. Authenticate and key limits by normalized verified
   identity/token; retain a separately bounded pre-authentication limit. Add
   equivalent-header tests that must share the same allowance.

5. **A5 / P2 — A document reference survives navigation into another form.**
   `apps/extension/entrypoints/sidepanel/App.tsx:107` keeps the reference outside
   document-bound state. Type a fictional reference on ECI, navigate the same
   tab to a different NSP profile and re-read: the old reference is still present
   and participates in comparisons. Reset document-owned reference, acknowledgment
   and cached snapshot state when their document/session ends. Merely hiding the
   inputs is not clearing their data. Add a navigation test with a populated
   reference and acknowledgment.

6. **A6 / P2 — Review revisions omit material displayed information.**
   `packages/rules/src/review.ts:29` omits option labels, descriptions and native
   constraints. After acknowledgment, changing the selected radio's visible label
   updated the panel but left the acknowledgment and revision current. Changing
   the PIN pattern and explicitly re-reading also retained that acknowledgment.
   Include all material used in the review/interpretation in its revision and
   cover metadata-only changes. The reader's digest at `reader.ts:270` and narrow
   mutation filter also need to track these changes, not just value/required
   changes. Never assert “any material change invalidates” from the current tests.

7. **A7 / P2 — Inactive choice values are still collected through options.**
   `apps/extension/entrypoints/reader.ts:157` always calls `optionsOf` even when
   the field is inactive. A hidden checked checkbox and hidden selected option
   had `value: null` but retained the hidden values and selection in `options`.
   Redact the inactive selection/value representation consistently, including
   choices; assert on the complete snapshot, not only the top-level value.

8. **A8 / P2 — Independent radio groups can silently disappear.**
   `apps/extension/entrypoints/reader.ts:232` groups by `form.id` and input name.
   Two separate forms without IDs, each containing `name="choice"`, yielded
   one group and no coverage warning. Use the form element's identity and native
   form ownership, not its optional HTML ID. Test nameless radios and associated
   controls outside the form as well as identical names in different forms.

9. **A9 / P2 — Client cancellation does not reliably cancel provider work.**
   `apps/api/src/ai.controller.ts:93` listens to the incoming request's `close`
   event after body parsing. With a controlled delayed provider, aborting the
   client after the provider received the request did not cancel the upstream
   connection; it completed normally. Observe response/socket closure during
   processing, handle an already aborted request, and remove listeners on
   completion. Test cancellation after a fully uploaded JSON/audio body.

10. **A10 / P2 — Live pack selection is host-wide, not workflow-specific.**
    `packages/rules/src/packs.ts:163` selects the ECI or NSP pack for the whole
    host, even with no matching fields. The snapshot carries origin but no
    workflow path, so it cannot distinguish Form 6 from another ECI form by route.
    Keep practice matching explicit; use verified workflow evidence for live
    matching and leave unrecognized stages generic/unchecked. The unverified
    label is honest, but does not implement the master specification's scope rule.

## Implementation follow-up from c8c23ca

Starting point: clean `main` at `c8c23ca`. No additional `AGENTS.md` instructions

### Fixes

1. **Cancelled audio:** each recorder owns its buffer. Data, stop and timer
   callbacks check both the session generation and recorder identity before
   touching anything. Cancelling invalidates the generation before stopping the
   recorder and releasing its tracks. A delayed permission result releases only
   its own stream; it cannot clear a newer permission attempt. The 15-second
   limit and manual correction/submission behavior remain.
2. **A1, remaining interpretation lifetime:** cloud access is independent of
   recording eligibility. Consent, credential value, document, field and
   eligibility transitions invalidate work synchronously during React layout
   cleanup, as does unmount. Request creation and reply acceptance recheck the
   current session. Identifier fields still allow text-only meaning requests
   while recording stays unavailable. Help requests also expire on credential
   replacement, even when both credentials are nonempty.
3. **A2:** direct scans carry a lifecycle generation and attempt identity.
   Navigation, closure, unmount and superseding requests invalidate old work;
   checks after injection and message completion reject stale successes and
   failures. A rescan cannot replace a newer pushed sequence. Invalidated
   rescans return `null`, so final review cannot acknowledge their responses.
   Existing sender/tab/document checks for pushed messages remain in place.
4. **A3:** secret matching splits snake_case, camelCase, acronym boundaries,
   hyphens and spaces, and checks type, autocomplete, names, IDs and all relevant
   labels before collecting values/options. If any radio member is sensitive,
   the whole group is omitted with explicit sensitive gaps. Native form
   ownership is used to inspect every member, including externally associated
   controls. This also fixes **A8**: separate forms without IDs and unnamed
   radios no longer collapse into one group. Postal PIN and ordinary number
   fields remain readable.
5. **A4:** one parser handles Bearer scheme/spacing. HMAC and expiry verification
   precede authenticated limits, which use a hash of the verified subject and
   the route handler, not the raw Authorization header. Renewed credentials for
   the same subject share their allowance; distinct subjects are independent.
   A separate limit covers all authentication attempts per socket peer before
   verification (default 600/min, configurable with
   `PRE_AUTH_RATE_LIMIT_PER_MINUTE`). Forwarded address headers are ignored.
   Both maps cap at 10,000 entries, expire unused entries on the next request,
   and reject new keys at capacity without evicting live allowances. Signed
   expiry claims must be finite safe integers. No credentials are logged.

### Fixes

1. **Identical control replacement (reader, hook, panel).** A field now
   carries the identifier of the form that owns it (`form` in the contract,
   stable like `fieldId`), and the reader's push digest includes every
   control's identity as well as its content, so a clone replacement is pushed
   although nothing reviewable changed and the acknowledgment stays current.
   The panel relocates its selection with a pure rule
   (`sidepanel/relocate.ts`): same reviewed metadata within the same surviving
   form, or within a brand-new form when the whole form was re-rendered, and
   among identical controls the same place in document order while their
   number is unchanged. Anything else is announced as replaced-and-uncertain or
   removed, the person is asked to choose from the list, and no page control
   is focused on a guess. A focus request that finds its control gone re-reads
   the page and retries once, against the unambiguous stand-in only. Names are
   never treated as unique: a same-named control in another surviving form is
   never taken for the lost one.
2. **A5, document-owned state (panel).** The reference spelling, the
   acknowledgment, the selection, revealed values, the last announcement and
   the field list held for relocation are reset during render the moment the
   connection reports the document ended (`stale`, `closed`) or a snapshot of
   another document arrives. Because it happens in render, no commit shows the
   old data and no delayed callback can revive it; `announce` additionally drops
   any message whose page state is no longer current instead of storing it. A
   rescan or re-read of the same document keeps everything. The hook already
   cleared its own snapshot and document binding on those transitions.
3. **A7, inactive choices (reader).** `optionsOf` and the radio-group reader
   take the control's applicability: an inactive select, checkbox or radio
   group keeps its labels and offered values, has `value: null`, and every
   option is `selected: false`. Secret exclusion still runs before any member
   or option is read. Values are read fresh when the control becomes
   applicable again.
4. **A9, caller cancellation (API).** The controller no longer listens on the
   request stream, whose `close` fires as soon as the body has been read; it
   watches the response's `close` before `writableFinished`, aborts immediately
   when the response is already destroyed, and removes the listener when the
   work ends. The provider adapter's backoff is abortable, an aborted signal is
   checked before every attempt and reported as `cancelled` rather than
   retried, and an aborted body read is `cancelled` too. The error filter
   writes nothing to a destroyed or already-ended response. Normal body
   completion is not a disconnect. Nothing claims to recall what a provider
   already received; the panel and website wording say so.
5. **Date of birth (rules).** `parseDate` reads day/month/year text or a
   native date control's ISO value, rejects year 0 and impossible dates;
   `date-future` rejects a date after today, where today is the local
   calendar date of the machine running the check (documented policy,
   injectable as `today` for tests, no time-zone conversion); `date-bounds`
   enforces only a native date control's own `min`/`max`, because no reviewed
   source states a portal bound; and `dob-eligibility-unchecked` states on
   every page with a mapped date of birth that no minimum age, maximum age or
   cutoff was applied. Validity and eligibility stay separate.
6. **Hindi number words: deferred.** No local parser exists or is claimed. The
   consent-gated service path remains the only route from speech to a
   suggested date; the local engine checks that suggestion with the same date
   rules and the person confirms it. The website's limitations page, the
   product specification and the architecture note say so explicitly.
