## Reproduced defects and next checks

P1 means fix before using real data or enabling a shared cloud pilot. P2 means
fix before marking the relevant feature complete. P3 is documentation cleanup.

1. **A1 / P1 — Cloud consent is not enforced through the operation lifetime.**
   In `apps/extension/entrypoints/sidepanel/SpeechAssist.tsx:489`, `fetchHelp`
   does not check consent; its button only sets `aria-disabled`. With a stored
   fictional credential and consent OFF, pressing Enter issued
   `POST /v1/speech/help`. Separately, start a fake recording, switch cloud OFF,
   and wait: `POST /v1/speech/transcribe` was still issued about 15 seconds later.
   The recording callbacks at lines 195–239 retain the earlier session, and
   revocation does not stop/discard them. Enforce consent at request time, abort
   pending work and stop/discard recordings on revocation. Add regression checks
   for off-state keyboard activation, mid-recording revocation and credentials
   removed while an operation is pending.

2. **A2 / P1 — Late scan replies can restore an obsolete document.**
   `apps/extension/entrypoints/sidepanel/useFormReader.ts:55` accepts direct scan
   replies after checking only the tab ID. Hold an already captured NSP reply,
   navigate that tab to ECI, wait for the stale state, then release the reply:
   the panel displays the old NSP OTR field beside the ECI page. `decideInbox`
   protects pushed messages, but not this path. Bind each request to a lifecycle
   generation and reject replies after navigation, close, unmount or a newer
   request. Exercise delayed direct replies, not only the pure inbox function.

3. **A3 / P1 — Common secret-field names bypass exclusion.**
   `apps/extension/entrypoints/reader.ts:24` uses ASCII word boundaries that do
   not split underscores. Synthetic controls named `otp_code` and `card_number`
   were returned with their values, while a control with `autocomplete="cc-number"`
   was correctly excluded. Normalize name/ID tokens and check standard secret
   metadata before reading any value or option. Add snake_case/camelCase,
   translated-label and group-member cases. Do not fix this by labelling every
   numeric value or postal PIN as a secret.

4. **A4 / P1 — The same credential can bypass its rate limit.**
   `apps/api/src/http.ts:82` keys limits by the raw Authorization header before
   authentication normalizes it. With a one-request limit, the same valid token
   returned statuses `200, 429, 200, 200` when sent with one, one, two and three
   spaces after `Bearer`. Authenticate and key limits by normalized verified
   identity/token; retain a separately bounded pre-authentication limit. Add
   equivalent-header tests that must share the same allowance.

5. **A5 / P2 — A document reference survives navigation into another form.**
   `apps/extension/entrypoints/sidepanel/App.tsx:107` keeps the reference outside
   document-bound state. Type a fictional reference on ECI, navigate the same
   tab to a different NSP profile and re-read: the old reference is still present
   and participates in comparisons. Reset document-owned reference, acknowledgment
   and cached snapshot state when their document/session ends. Merely hiding the
   inputs is not clearing their data. Add a navigation test with a populated
   reference and acknowledgment.

6. **A6 / P2 — Review revisions omit material displayed information.**
   `packages/rules/src/review.ts:29` omits option labels, descriptions and native
   constraints. After acknowledgment, changing the selected radio's visible label
   updated the panel but left the acknowledgment and revision current. Changing
   the PIN pattern and explicitly re-reading also retained that acknowledgment.
   Include all material used in the review/interpretation in its revision and
   cover metadata-only changes. The reader's digest at `reader.ts:270` and narrow
   mutation filter also need to track these changes, not just value/required
   changes. Never assert “any material change invalidates” from the current tests.

7. **A7 / P2 — Inactive choice values are still collected through options.**
   `apps/extension/entrypoints/reader.ts:157` always calls `optionsOf` even when
   the field is inactive. A hidden checked checkbox and hidden selected option
   had `value: null` but retained the hidden values and selection in `options`.
   Redact the inactive selection/value representation consistently, including
   choices; assert on the complete snapshot, not only the top-level value.

8. **A8 / P2 — Independent radio groups can silently disappear.**
   `apps/extension/entrypoints/reader.ts:232` groups by `form.id` and input name.
   Two separate forms without IDs, each containing `name="choice"`, yielded
   one group and no coverage warning. Use the form element's identity and native
   form ownership, not its optional HTML ID. Test nameless radios and associated
   controls outside the form as well as identical names in different forms.

9. **A9 / P2 — Client cancellation does not reliably cancel provider work.**
   `apps/api/src/ai.controller.ts:93` listens to the incoming request's `close`
   event after body parsing. With a controlled delayed provider, aborting the
   client after the provider received the request did not cancel the upstream
   connection; it completed normally. Observe response/socket closure during
   processing, handle an already aborted request, and remove listeners on
   completion. Test cancellation after a fully uploaded JSON/audio body.

10. **A10 / P2 — Live pack selection is host-wide, not workflow-specific.**
    `packages/rules/src/packs.ts:163` selects the ECI or NSP pack for the whole
    host, even with no matching fields. The snapshot carries origin but no
    workflow path, so it cannot distinguish Form 6 from another ECI form by route.
    Keep practice matching explicit; use verified workflow evidence for live
    matching and leave unrecognized stages generic/unchecked. The unverified
    label is honest, but does not implement the master specification's scope rule.

## Remaining implementation scope and documentation

- DOB checks cover syntax/month/day arithmetic, not future birth dates or
  applicable boundaries. `calendarProblem('01/01/0000')` and
  `calendarProblem('01/01/2099')` both returned `null`; the DOB validator adds no
  later temporal check. Define the supported civil-year range and add the planned
  future-DOB check, using a controlled reference date. This is distinct from
  deciding eligibility.
- There is no local expression interpretation before the language-model request.
  Devanagari digit normalization is implemented; Hindi number-word interpretation
  is explicitly deferred in `docs/testing.md`. The original local-first parsing
  goal should remain incomplete unless its scope is explicitly revised.
- `README.md:165` still says there is no companion website, and
  `App.tsx:470` says review completion is unavailable. Both conflict with the
  current implementation. Update these and the release's “no release-blocking
  failure” wording after the new regression tests and fixes pass.
